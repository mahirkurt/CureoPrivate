## 1. Motivation

`publish_audit` (v0.2.1) **detects** 19 gate-level failures but does not **fix** them. The Düstur build empirically demonstrated that ~%90 of build effort is spent writing ad-hoc remediation scripts (alias rewriters, variant calculators, Code Connect templates, manifest generators). This RFC closes the detect-fix gap by introducing a parallel **`auto_remediate`** subsystem that consumes audit reports and produces actionable remediation artifacts in two output channels:

1. **Static-source PR** — Git patch / diff applied to the static source-of-truth (DTCG JSON, component specs, code-connect mappings, library-registry, etc.)
2. **Figma plugin script** — TypeScript file that, when run in Figma's Dev Console, applies the fix directly to the live document (for cases where the live state has drifted from the static source)

---

## 2. Design Goals

| Goal | Non-Goal |
|------|----------|
| Idempotent remediations (running twice = same result) | Auto-merging PRs without human review |
| Each strategy is independent (plugin-style) | Cross-strategy dependencies / cascading fixes |
| Generates code in user's language (TR/EN per locale) | Replacing audit's detection role |
| Conservative: never deletes user content without explicit `--destructive` flag | Aggressive optimization that changes user intent |
| Audit report → remediation plan is deterministic | Statistical / ML-based fix generation |

## 3. Architecture

```
figma-forge/
└── scripts/
    └── auto_remediate/
        ├── __init__.py
        ├── base.py                          # RemediationStrategy ABC + RemediationResult
        ├── runner.py                        # CLI orchestration; audit-report → remediations
        ├── output/
        │   ├── __init__.py
        │   ├── pr_writer.py                 # Git diff / patch formatter
        │   └── plugin_writer.py             # Figma plugin TS script generator
        └── strategies/
            ├── __init__.py
            ├── _registry.py                 # @register_strategy(gate_id) decorator
            ├── g07_variant_matrix.py        # G7 — variant Cartesian product mismatch
            ├── g08_component_naming.py      # G8 — snake_case → PascalCase rewriter
            ├── g13_alias_resolution.py      # G13 — DTCG alias path normalizer
            ├── g14_icons_are_components.py  # G14 — orphan SVG → component
            ├── g15_icon_size_grid.py        # G15 — viewBox normalize
            ├── g17_code_connect_badges.py   # G17 — Code Connect mapping generator
            └── _composite_typography.py     # L2 — composite type detection + Text Styles route
```

### 3.1 Strategy Contract

```python
class RemediationStrategy(ABC):
    """ABC for a single gate's remediation."""

    gate_id: ClassVar[int]            # e.g. 13
    title: ClassVar[str]              # e.g. "DTCG alias path normalizer"
    output_channels: ClassVar[tuple]  # ("pr",) or ("pr", "plugin") or ("plugin",)

    @abstractmethod
    def plan(self, failure: GateResult, ctx: RemediationContext) -> list[RemediationAction]:
        """Examine a single gate failure; return ordered action list. May return []."""

    @abstractmethod
    def render(self, action: RemediationAction, channel: str) -> str:
        """Convert action → channel-specific output string (PR patch or TS script)."""
```

### 3.2 Output Channels

- **PR Output** — diff/patch in unified format; designed to apply via `git apply` or be opened as a PR. Includes commit-message draft.
- **Plugin Output** — single `.ts` file. Uses `figma.*` API. Runs inside Figma Dev Console / plugin sandbox.

User selects channel via CLI:

```bash
figma-forge auto-remediate \
    --audit-report audit-report.md \
    --output-channel pr \
    --output-dir ./remediations/ \
    --apply false        # if true, attempts git apply
```

## 4. MVP Strategies (v0.3.0-alpha.1 — first sprint)

Selected by impact analysis from the Düstur build:

### Strategy 1 — G13 Alias Path Normalization (L1)

**Detect:** `publish_audit` G13 reports `unresolved_aliases >= 1`.

**Plan:**
1. Parse merged DTCG JSON
2. Walk every leaf node; identify `$value` matching alias pattern `{...}`
3. For each unresolved alias, search the DTCG tree for any path **ending in** the alias target
4. If exactly 1 candidate found → propose rewrite
5. If 0 or 2+ candidates → flag as ambiguous, skip

**Render — PR channel:**

```diff
--- a/tokens/semantic/tier.json
+++ b/tokens/semantic/tier.json
@@ -7,5 +7,5 @@
   "anayasa": {
-    "primary":  {"$type": "color", "$value": "{tbk.9}"},
+    "primary":  {"$type": "color", "$value": "{color.tbk.9}"},
   }
```

**Render — Plugin channel:**

```typescript
const variable = figma.variables.getVariableById('VariableID:301:1234');
if (variable && variable.name === 'semantic/anayasa/primary') {
    variable.setValueForMode('mode-light', {
        type: 'VARIABLE_ALIAS',
        id: figma.variables.getVariableByName('color/tbk/9')?.id ?? variable.id
    });
}
```

### Strategy 2 — G17 Code Connect Mapping Generator (L9)

**Detect:** G17 reports components without Code Connect badge.

**Plan:**
1. Read component spec JSON
2. Extract `variants.axes` → props mapping
3. Generate React + Web Component + CSS class templates per Düstur conventions
4. Write to `code-connect/<component-id>.json`

**Render — PR channel:** Multi-file diff creating new `code-connect/*.json` files.

### Strategy 3 — G14 Icons-Are-Components SVG Normalizer (L6)

**Detect:** G14 reports SVG asset that is not a Figma component, or icon has non-canonical size.

**Plan:**
1. Identify SVG source (icons/svg/*)
2. Normalize: stroke 1.5px, linecap=round, viewBox 24×24, fill=none, add `<title>` if missing
3. Apply Tabler/Lucide adapter if applicable

**Render — PR channel:** Patched SVG file. Render — plugin channel: `figma.createComponentFromNode()` calls for each SVG.

## 5. Calibration Integration

Auto-remediation should **respect calibration data** (v0.2.1 feature). If a gate's calibration report shows a recurring boundary case, the remediation strategy can:

1. Lower its confidence threshold for that gate
2. Switch from auto-apply to suggest-only

```python
@register_strategy(gate_id=13)
class AliasResolutionStrategy(RemediationStrategy):
    def plan(self, failure, ctx):
        calibration = ctx.load_calibration(gate_id=13)
        if calibration and calibration.unresolved_rate > 0.4:
            # Too many ambiguous → propose, don't auto-apply
            self.output_channels = ("pr",)  # suggest only
        return self._scan_unresolved(failure)
```

## 6. CLI Spec

```
figma-forge auto-remediate [OPTIONS]

REQUIRED:
  --audit-report PATH       Path to publish_audit Markdown or JSON report
  --output-channel CHANNEL  pr | plugin | both

OPTIONAL:
  --output-dir DIR          Default: ./remediations/
  --strategies LIST         Comma-separated list of strategy IDs to run; default: all
  --calibration-dir DIR     Optional calibration sidecar dir for confidence tuning
  --apply BOOL              If pr channel: git apply patches automatically (default false)
  --locale LOCALE           Output locale: tr-TR | en-US (default: en-US)
  --verbose                 Print progress to stderr
  --dry-run                 Plan only; no file writes

EXIT CODES:
  0  Remediation plan produced and (if --apply) applied successfully
  1  Audit report had no actionable failures (no-op)
  2  Cannot run (invalid audit report, missing strategy, etc.)
  3  Apply failed (only if --apply)
```

## 7. Audit Report JSON Format (Prerequisite)

Currently `publish_audit` outputs Markdown only. v0.3.0 must add **structured JSON** output for machine-readable remediation input:

```json
{
  "schema_version": "1.0",
  "audit_timestamp": "2026-05-26T10:00:00Z",
  "library_registry": "library-registry.json",
  "score": 7.4,
  "band": "STRONG",
  "gates": [
    {
      "id": 13,
      "name": "Token alias resolvable",
      "result": "FAIL",
      "severity": "MAJOR",
      "details": {
        "unresolved_count": 89,
        "samples": [
          {"path": "color.semantic.anayasa.primary", "alias": "{tbk.9}", "expected": "{color.tbk.9}"}
        ]
      }
    }
  ]
}
```

Output via new flag: `publish_audit.py ... --output-format json`.

## 8. Testing Strategy

- **Unit:** Each strategy has 5-10 fixture cases (golden output)
- **Integration:** End-to-end with synthetic audit report → applied remediation → re-audit → all gates pass
- **Regression:** Run against Düstur bundle (production-grade); v0.3.0 should reproduce the manual remediations we did

**Coverage target:** 90%+ for new code, ≥80% mutation-test survival via `mutmut`.

## 9. Backwards Compatibility

- No changes to existing CLI signatures
- New `--output-format json` flag on `publish_audit.py` is additive
- `auto_remediate` is a new subcommand; opt-in only

**SemVer impact:** **MINOR** bump (v0.2.1 → v0.3.0).

## 12. Open Questions

1. **PR creation API**: Should figma-forge use `gh` CLI or write raw `.patch` files? *Decision: raw `.patch` first; `gh` integration in v0.3.1.*
2. **Plugin script signing**: Figma plugin manifest signing required? *Decision: scripts are user-paste, not packaged plugins → no signing for MVP.*
3. **Locale priority**: TR-TR or EN-US default? *Decision: EN-US for code/CLI output; comments and PR descriptions follow `--locale`.*
