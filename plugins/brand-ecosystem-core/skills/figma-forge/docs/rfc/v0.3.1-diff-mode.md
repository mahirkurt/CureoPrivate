## 1. Motivation

Once `publish_audit` produces JSON-format reports (v0.3.0), comparing **two audit reports** unlocks regression tracking: did this week's library improve over last week's? Did the auto-remediate PR actually fix the gates it claimed to fix? Which gates worsened?

The Düstur build had no such mechanism — we ran static-lint once, called it done. In real DS maintenance, audits run on every commit and the trend matters more than any single snapshot.

This RFC defines a `diff` subcommand that consumes two audit JSON reports and emits a delta report (Markdown + JSON sidecar).

---

## 2. Design

### 2.1 CLI

```bash
figma-forge audit-diff \
    --base audit-2026-05-19.json \
    --head audit-2026-05-26.json \
    --output diff-report.md \
    --baseline-strict false
```

### 2.2 Delta Categories

For each gate, classify the change:

| Δ Category | Base | Head | Meaning |
|------------|------|------|---------|
| 🟢 **Fixed** | FAIL/WARN | PASS | Regression resolved |
| 🔴 **Regressed** | PASS | FAIL/WARN | New issue introduced |
| 🟡 **Worsened** | FAIL | FAIL (higher sample count) | Same failure, worse impact |
| 🔵 **Improved** | FAIL | FAIL (lower sample count) | Partial fix |
| ⚪ **Unchanged** | Same | Same | No change |
| ⚫ **Added** | (missing) | Any | New gate in head |
| ⚫ **Removed** | Any | (missing) | Gate removed from head |

### 2.3 Sample-Level Delta

For gates with sample arrays (G7, G13, G14, G15, G17), compute set diff of sample IDs:

```
G13 base samples: ["semantic.anayasa.primary", "semantic.aym.primary", ...]
G13 head samples: ["semantic.aym.primary"]
→ resolved: ["semantic.anayasa.primary"]
→ remaining: ["semantic.aym.primary"]
→ new: []
```

### 2.4 Calibration Delta (Conditional on v0.2.1 calibration data)

If both audits ran with `--calibration-mode`, compute:

* Boundary-decision count delta (more boundary cases = thresholds slipping)
* Feature distribution KL divergence (per-gate confidence shift)
* Skip-reason histogram changes (e.g. more "no_bbox" skips = scanning quality dropped)

### 2.5 Score Delta

Top-line score delta (e.g. `7.4 → 8.6 (+1.2)`) plus band transition (`STRONG → EXEMPLARY`).

---

## 3. Output Format

**Markdown report** with the delta table, sample-level breakdowns, and recommendations. **JSON sidecar** for CI/CD pipelines:

```json
{
  "schema_version": "1.0",
  "base_audit": "...",
  "head_audit": "...",
  "score_delta": {"base": 7.4, "head": 8.6, "diff": 1.2, "band_transition": "STRONG → EXEMPLARY"},
  "gate_deltas": [
    {"gate_id": 13, "category": "fixed", "samples_resolved": 89, "samples_new": 0},
    {"gate_id": 17, "category": "regressed", "samples_resolved": 0, "samples_new": 3}
  ],
  "calibration_delta": {"boundary_decisions_delta": -5, "kl_divergence_summary": {...}}
}
```

---

## 4. Integration with Auto-Remediate

When auto-remediate runs after a `diff` shows new failures, the diff output feeds remediation prioritization:

```bash
# CI/CD: each PR runs audit + diff + auto-remediate
figma-forge publish-audit --output head.json --library-registry library-registry.json
figma-forge audit-diff --base main-audit.json --head head.json --output diff.md
figma-forge auto-remediate --audit-report head.json --strategies "$(jq -r '.gate_deltas[] | select(.category == "regressed") | .gate_id' diff.json | paste -sd,)"
```
