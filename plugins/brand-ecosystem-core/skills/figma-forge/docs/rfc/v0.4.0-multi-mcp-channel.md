## 1. Motivation

v0.2.x operates against a single MCP server (Anthropic-hosted Figma MCP) plus REST fallback. The Düstur build did not exercise alternative MCP channels, but the design space — multiple IDE-embedded MCP servers (Cursor, Zed, Cline), CI/CD-hosted MCP servers, self-hosted Codebase MCP — demands transport abstraction.

v0.4.0 introduces:

1. **MCP transport adapter layer** — figma-forge no longer hard-codes the channel
2. **Cursor / Codebase MCP support** — first concrete alternative transport
3. **Channel negotiation** — pick the best available channel automatically based on capabilities

## 2. Architecture

### 2.1 Transport Abstraction

```
figma-forge/figma_forge/transport/
├── __init__.py
├── base.py                  # AbstractFigmaTransport ABC
├── adapters/
│   ├── anthropic_mcp.py     # Default — claude.ai-hosted MCP
│   ├── cursor_mcp.py        # NEW — Cursor IDE MCP integration
│   ├── codebase_mcp.py      # NEW — self-hosted Codebase MCP
│   └── rest_fallback.py     # REST API direct (no MCP)
└── negotiation.py           # Channel capability discovery + selection
```

### 2.2 Capability Matrix

Each transport declares its supported operations:

| Operation | Anthropic MCP | Cursor MCP | Codebase MCP | REST |
|-----------|:-------------:|:----------:|:------------:|:----:|
| `get_file_metadata` | ✅ | ✅ | ✅ | ✅ |
| `read_variables` | ✅ | ✅ | ✅ | ✅ |
| `write_variables` | ✅ | ⚠️ (subset) | ✅ | ✅ |
| `bulk_create_components` | ✅ | ❌ | ✅ | ✅ |
| `attach_code_connect` | ✅ | ✅ | ❌ | ⚠️ (manual) |
| `apply_remediation_plugin` | ✅ | ✅ | ❌ | ❌ |

Channel negotiation picks the highest-capability available transport at runtime.

### 2.3 Configuration

```yaml
# .figma-forge.yml (NEW v0.4.0 config file)
transport:
  preferred_order:
    - cursor_mcp
    - anthropic_mcp
    - rest_fallback
  fallback_strategy: graceful  # graceful | strict | first-available

  endpoints:
    cursor_mcp: "http://localhost:3000/mcp"
    codebase_mcp: "https://codebase.example.com/mcp"
```

## 3. Migration Plan

v0.4.0 is **backwards-compatible** because:

* Default transport remains Anthropic MCP (v0.2.x behavior)
* All v0.3.x CLI flags continue to work
* `.figma-forge.yml` is optional

Breaking changes deferred to v1.0.0 (e.g. removing the legacy REST fallback unless explicitly requested).

## 4. New CLI Flags

```
--transport CHANNEL          Force a specific transport
--list-transports            Show available transports + capabilities
--transport-config FILE      Path to .figma-forge.yml
```
