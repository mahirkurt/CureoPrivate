## 1. Motivation

v0.2.x → v0.4.x established figma-forge as a viable production tool. v1.0.0 marks the **semver freeze** — a backwards-compatibility commitment that allows third-party developers to build on top without churn risk.

Three principal v1.0.0 contributions:

1. **Stable Public API** — versioned, semver-protected interfaces for gates, strategies, transports, and audit reports
2. **`gates/` Drop-In Plugin Ecosystem** — third parties can ship their own gate definitions and remediation strategies as installable modules
3. **Anonymized Calibration Corpus** — opt-in community data sharing for heuristic improvement

## 2. Stable API Surface

### 2.1 What's Frozen

| API | Frozen | Notes |
|-----|--------|-------|
| `GateResult`, `Gate`, `GateFailure` dataclasses | ✅ | Field additions allowed; removals breaking |
| `@register_gate(N)`, `@register_strategy(N)` decorators | ✅ | |
| `@register_calibrator(N)` decorator | ✅ | |
| `MultiFileFigmaContext`, `RemediationContext` | ✅ | |
| `AbstractFigmaTransport` ABC | ✅ | |
| Audit JSON schema v1.0 | ✅ | Additions only via `$schema` v1.1 sidecar |
| CLI flag names | ✅ | New flags allowed; renames breaking |

### 2.2 What's NOT Frozen (Implementation Detail)

| Item | Status |
|------|--------|
| Internal gate algorithms | May change between versions |
| Heuristic threshold defaults | Tunable; bumps in PATCH versions OK |
| Output report Markdown layout | May evolve |
| Calibration sidecar internal fields | Schema may extend |

### 2.3 Deprecation Policy

Following Python's PEP 387:

1. **DeprecationWarning** in v1.x.y for at least 2 minor releases before removal in v2.0
2. **Migration guide** in CHANGELOG.md
3. **Compatibility shims** when feasible

## 3. Plugin Ecosystem

### 3.1 `gates/` Drop-In Modules

Third-party developers can ship Python packages with this structure:

```
my-figma-forge-extensions/
├── pyproject.toml             # entry_points["figma_forge.gates"] = "g20:check"
├── my_extensions/
│   ├── __init__.py
│   ├── g20_brand_compliance.py
│   ├── g21_dark_mode_parity.py
│   └── g22_motion_consistency.py
```

`figma_forge` discovers them at startup via `importlib.metadata.entry_points()`:

```python
# pyproject.toml
[project.entry_points."figma_forge.gates"]
g20_brand_compliance = "my_extensions.g20_brand_compliance:check"

[project.entry_points."figma_forge.strategies"]
g20_brand_remediation = "my_extensions.g20_brand_strategy:BrandComplianceStrategy"

[project.entry_points."figma_forge.transports"]
custom_mcp = "my_extensions.transport:CustomMCPTransport"
```

### 3.2 Plugin Marketplace

CLI command:

```bash
figma-forge plugins list-available    # Query a community registry
figma-forge plugins install <name>    # pip install + registration
figma-forge plugins list-installed
```

Community registry hosted at `plugins.figma-forge.dev` (or GitHub-Pages equivalent).

### 3.3 Plugin Quality Gates

Plugins are accepted into the marketplace only if they:

* Use the stable API exclusively
* Pass linting (`figma-forge plugin-lint`)
* Include a `compatibility` field declaring supported figma-forge versions
* Ship test coverage ≥80%
* Include security-policy declaration

## 4. Anonymized Calibration Corpus

### 4.1 Motivation

v0.2.1's calibration framework collects boundary-decision histograms that reveal whether each heuristic gate's threshold is well-calibrated against a given design system. Single-DS calibration data is limited; **community-aggregated** data unlocks evidence-based threshold tuning.

### 4.2 Opt-In Protocol

```bash
figma-forge publish-audit ... --calibration-mode --share-anonymized
```

The `--share-anonymized` flag:

1. Runs the existing `anonymize_calibration.py` pipeline (salted hashing of identifiers)
2. Uploads only:
   * Per-gate decision histograms (no node IDs, no file references)
   * Boundary-decision distribution shape
   * Skip-reason histograms
3. Never uploads token names, file keys, hex values, or filenames

### 4.3 Community Insight Reports

Quarterly aggregated reports published at `corpus.figma-forge.dev`:

* "G14 squareness threshold currently fires at 2.0 ± 0.3, but 73% of community DS prefer 1.5..."
* "Carbon-based libraries average 2.4 unresolved aliases per merge; Material-3-based libraries 1.1..."

These inform v1.x.y PATCH threshold tunings.

## 5. Sigstore / Cosign Integration (Optional)

Cryptographic attestation for published Figma libraries:

```bash
figma-forge publish-attestation \
    --library-registry library-registry.json \
    --signing-key cosign.key
```

Produces a Sigstore attestation:

```json
{
  "subject": [{"name": "library-registry.json", "digest": {"sha256": "..."}}],
  "predicate": {
    "audit_score": 8.6,
    "gates_passed": 19,
    "audit_timestamp": "2026-08-01T..."
  }
}
```

Allows downstream consumers to verify provenance:

```bash
cosign verify-blob --signature attestation.sig library-registry.json
```

## 8. Beyond v1.0.0

The v1.x line will focus on:

* Threshold tunings driven by calibration corpus (PATCH bumps)
* New gates and strategies (MINOR bumps via plugin ecosystem)
* Performance optimization
* Documentation completeness

Breaking changes deferred to v2.0.0 (no current candidates).
