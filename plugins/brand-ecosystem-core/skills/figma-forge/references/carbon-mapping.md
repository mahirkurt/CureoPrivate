# IBM Carbon Design System v11 → DTCG Mapping

Carbon Design System is IBM's open-source DS, currently at v11. This reference documents the canonical token tables for Carbon's color themes (white, g10, g90, g100), type ramp, spacing scale, motion, and elevation, and the canonical mappings to DTCG-shaped tokens that `figma-forge` produces.

## Color themes

Carbon ships four named themes. Each is a complete color token set:

| Theme | Background mode | Description |
|---|---|---|
| `white` | Light | The "lightest" theme; default for light UI |
| `g10` | Light | Subtle gray-tinted light theme |
| `g90` | Dark | Subtle gray-tinted dark theme |
| `g100` | Dark | The "darkest" theme; default for dark UI |

In DTCG output, themes become **modes** in the Semantic color collection:

```json
{
  "color": {
    "background": {
      "$type": "color",
      "$value": {
        "white": "#FFFFFF",
        "g10": "#F4F4F4",
        "g90": "#262626",
        "g100": "#161616"
      },
      "$extensions": {
        "com.ibm.carbon": "background"
      }
    }
  }
}
```

Carbon uses minimal radius — `0` for most, `4px` for some interactive elements, `50%` for circular badges.

## Component-level mapping

Carbon's component tokens (Button, TextInput, Tag, Modal, etc.) follow a `<component>-<part>-<state>` pattern:

```
button-primary
button-primary-hover
button-primary-active
button-secondary
button-tertiary
button-ghost
button-danger

text-input-background
text-input-border
text-input-focus
```

For `COMPONENTS_BUILD` mode with Carbon as source, `figma-forge` loads `references/component-spec-templates.md` and generates each component using these tokens.

## Caveats

- Carbon v11 dropped some v10 tokens; the mapper uses v11 nomenclature strictly. For v10 sources, use the migration tool from the Carbon team first.
- IBM Plex fonts must be installed in the user's Figma desktop (or downloaded via Google Fonts) for text styles to render correctly.
- Carbon's "fluid" tokens (responsive type/spacing that scales with viewport) aren't fully representable in Figma; the mapper uses fixed values from the desktop breakpoint by default.

## Source verification

Canonical Carbon v11 token values are maintained in IBM's `@carbon/themes` package on npm. The mapper's value table is regenerated from that package's published artifacts; the conversion script is in `scripts/carbon_to_dtcg.py`.

For up-to-date values when major Carbon versions ship, the user should regenerate the mapping table (the script can be re-run against a new `@carbon/themes` artifact).
